# Android input API integration

The user has authorized continued implementation of secure offline controller toggling. This replaces the failed retained-shell backend while preserving the full requirement, including the still-unsolved fresh phone-only activation without nearby Wi-Fi.

## Evidence and approach

The separate probe created and removed Sony 054c:0ce6 input devices after Auto Blocker activation, with USB and wireless debugging both zero. Timestamped logs and the user confirm this. `--no-restart` activation fails hidden-API lookup in an already running app. Normal instrumentation restart succeeds.

Use a temporary detached `am instrument -w --no-hidden-api-checks` launcher during activation. It starts the app under instrumentation and delegates exactly INJECT_EVENTS and ASSOCIATE_INPUT_DEVICE_TO_DISPLAY. These are broader than gamepad-only permissions; code exposes only fixed create/remove/status/exit operations. No retained shell helper, exported bootstrap provider, command RPC, or listener is needed after activation. App death ends instrumentation; stopping access explicitly ends instrumentation and terminates the app to ensure permission cleanup even when the launcher Binder has died.

Rejected alternatives: existing shell helper failed Auto Blocker; in-place instrumentation failed hidden-API lookup; broad persistent settings grants and repeated wireless-debugging re-enablement do not establish secure fresh offline setup. No vendor privilege exploit is included.

## Work and validation

1. Add fixed API gamepad backend; identify its newly registered device and preserve descriptor for existing UI/self-test logic. Retain exact UID checks on private commands.
2. Add instrumentation lifecycle and in-process connection. Remove exported shell bootstrap from manifest. Replace shell-helper activation command with detached instrumentation startup. Show honest Android-version and setup limits.
3. Build and run existing host checks. Install; validate controller ON/OFF against Android registry, cancellation, force-stop cleanup, and explicit access-stop cleanup.
4. Test actual phone-local activation with saved pairing credentials. Verify restarting the app does not kill the launcher before permissions are granted, and both debugging modes can be disabled afterward.
5. Restore Auto Blocker and Wi-Fi OFF. Obtain on/off self-test and CoD gameplay confirmation with only 8BitDo connected.
6. Investigate fresh activation without nearby Wi-Fi separately. Do not call the full goal achieved until it works without relaxing security or requiring a computer.

Version 0.3 remains experimental until these gates pass. Existing 0.1 and 0.2 release APKs remain untouched. Packaging/publishing a final release is not justified by registry success alone.
